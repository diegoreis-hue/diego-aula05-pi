**Criação do Repositório**

Criar um repositório é iniciar um projeto no GitHub. Ele funciona como uma pasta online onde ficam armazenados os arquivos do projeto, além do histórico de alterações feitas ao longo do tempo.


**Clone do Repositório**

Clonar um repositório significa copiar o projeto que está no GitHub para o meu computador.
Assim, posso fazer alterações e depois enviar para o repositório online.


**Criação de Branch**

Uma branch é como uma “linha alternativa” do projeto.
Ela permite que eu faça alterações sem modificar a versão principal.
É muito usada quando estamos trabalhando em equipe.


**Registro de Commits**

O commit é o registro das alterações feitas no projeto.
Cada commit possui uma mensagem explicando o que foi modificado.
Isso ajuda a organizar e acompanhar o desenvolvimento do projeto. É como se fosse um sheckPoint com um resumo do que foi feito.


**Envio das Alterações (Push)**

O push é a ação de enviar as alterações feitas no meu computador para o GitHub.
Assim, o repositório online fica atualizado.


**Atualização do Repositório Local (Pull)**

O pull serve para atualizar meu projeto local com as alterações que estão no GitHub.
É muito importante quando outras pessoas também estão trabalhando no projeto.


**Criação de Issues**

As Issues servem para registrar tarefas, problemas ou sugestões dentro do projeto.
Elas ajudam na organização do que precisa ser feito.


**Organização com Milestone**

Milestone é uma forma de organizar tarefas por etapas ou metas.
Por exemplo: “Entrega da primeira versão” ou “Finalização do site”.


**Gerenciamento com Project**

O Project é um quadro de organização.
Ele permite visualizar tarefas como:
A fazer, em andamento, concluído. 
Isso facilita o controle do projeto.


**Abertura de Pull Request**

O Pull Request é uma solicitação para que as alterações feitas em uma branch sejam analisadas e adicionadas à branch principal.
Ele permite revisão antes da junção final.


**Realização de Merge**

O Merge é a junção das alterações de uma branch com a branch principal.
Após a aprovação do Pull Request, as mudanças passam a fazer parte oficialmente do projeto.
